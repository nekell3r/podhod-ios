# Подход для iOS

Нативный клиент SwiftUI для iPhone, iOS 17+. Программа по календарным неделям и повторяемому шаблону, запись подходов, отдых, история, время тренировки, карточки упражнений и прогресс. В разделе питания — рецепты, продукты, дневник приёмов пищи, ручные цели КБЖУ и свои рецепты.

Общий сервер: [podhod-backend](https://github.com/nekell3r/podhod-backend). Клиент Android: [podhod-android](https://github.com/nekell3r/podhod-android).

## План развития

Очередь масштабной доработки и критерии: [ROADMAP.ru.md](docs/ROADMAP.ru.md). Рабочая тренировка: компактные строки веса/повторов/запаса, обзор упражнений, добавление и удаление незавершённых подходов, подстановка прошлого результата и закреплённый отдых −30/+30 секунд. Можно заменить оставшуюся часть упражнения, сохранив исходную карточку, добавить упражнение и изменить порядок. Прогресс показывает периоды и исходные подходы рекордов. Питание включает дневник и синхронизацию; многонедельные циклы и суперсеты описаны ниже. В очереди — замеры/фото, Live Activity и база знаний.

В «Программе» открой «Настроить цикл»: 2–12 недель из текущего шаблона, повторение и предпросмотр перед применением. «Волна подходов» меняет только число подходов по явно показанному правилу; вес, повторы и запас не заполняются. Каждый день фазы редактируется отдельно: варианты A/B/C, тип нагрузки, сложность и группы суперсетов. Цикл применяется только при создании отсутствующей календарной недели; пропуски не сдвигают даты, изменения не переписывают созданные недели и историю. В тренировке упражнения группы чередуются, отдых запускается после круга. Через «Состав и порядок» можно создать группу, добавить круг или распустить её с сохранением выполненных связей и черновиков.

В питании переключай «Дневник / Рецепты». В дневнике выбери дату и приём пищи, затем продукт, рецепт или ручной состав. Для рецепта сначала подтверждается готовая масса, потом вводятся граммы или порции. Цели, свои рецепты и экспорт JSON доступны в меню дневника. Новые цели и изменения рецептов не переписывают уже записанные дни; отметки протеина не добавляют еду автоматически.

## Запуск

Нужен полный Xcode. Открой `Podhod.xcodeproj`, схема `Podhod`.

```sh
cp Config/Local.xcconfig.example Config/Local.xcconfig
```

Укажи собственный hostname API в `PODHOD_API_HOST` локального файла. `Config/Podhod.xcconfig` подключает его опционально; без настройки используется фиктивный `api.example.com`, а локальные программы и история остаются доступны без входа. Реальный адрес не хранится в исходниках: build setting попадает в `PodhodServerURL` Info.plist. OAuth public client — `podhod-ios`, callback — `podhod://oauth/callback`.

В проекте нет Apple Account, сертификатов или provisioning profiles. Для установки выбери собственную команду подписи либо подпиши unsigned IPA подходящим сертификатом на устройстве.

## Проверка и локальный выпуск

```sh
swift test
python3 -m unittest discover -s scripts/tests
python3 scripts/release_local.py 1.5 6
```

Автоматический выпуск из `main` настроен через GitHub Actions: тесты, unsigned IPA и публикация в существующий источник Feather. Версия и build увеличиваются автоматически; настройка и ручной резервный выпуск описаны в [RELEASING.md](RELEASING.md).

Последняя команда только проверяет клиент, собирает unsigned IPA для реального iPhone без Simulator и формирует артефакты в `.build/releases/`. Для выпуска обновления по умолчанию также обязательна публикация в существующем источнике Feather: загрузи настройки из игнорируемого `.env.local` и выполни команду с `--publish`. Только локальную сборку используй по явному запросу. Готовый проверенный IPA можно опубликовать без повторной сборки. После выпуска проверь публичный IPA и `source.json`; подробнее: [RELEASING.md](RELEASING.md).

## Данные и синхронизация

Изменения сохраняются локально сразу. После входа клиент синхронизирует шаблон, текущий цикл, недели, активную тренировку, историю и отметки протеина с общим API. CAS защищает от молчаливой перезаписи конкурирующих изменений; пользовательские данные и OAuth-токены не включаются в исходники или IPA. Токены находятся в Keychain.

Архив тренировок — v6; старые форматы читаются с резервной копией перед первой записью. Цикл и pending-запрос хранятся атомарно с тренировками; при конфликте сохраняются обе версии для явного выбора. Метки структуры защищены от стирания старыми клиентами. Журнал явных удалений незавершённых подходов сохраняется вместе с тренировкой, переживает офлайн-завершение и передаётся в active/history API. Выполненные подходы не удаляются. Backend с поддержкой нового контракта выпускается перед клиентом. При обновлении устанавливай приложение поверх прежнего, сохраняя Bundle ID и совместимую подпись. Не удаляй приложение ради обновления.

Вход поддерживает логин и Telegram через общий Keycloak. Чтобы сохранить прежнюю историю при переходе на Telegram, сначала войди прежним способом и выбери «Привязать Telegram к аккаунту». Новые Telegram-пользователи получают независимый subject и пустое серверное пространство; Telegram username не используется для сопоставления владельцев.

На устройстве можно менять аккаунты: `AccountWorkspaces` хранит архивы отдельно, выход открывает гостевой режим. Перед первой миграцией прежние файлы тренировок, протеина, синхронизации и питания копируются в `legacy-backups`. Архив, уже связанный с subject, не передаётся другому аккаунту. Гостевые данные при первом входе нового аккаунта принимаются отдельно от существующих архивов; после принятия создаётся новый гостевой каталог, в том числе при переносе только питания. При возврате восстанавливается незавершённая тренировка; время под другим аккаунтом не засчитывается как упражнение.

Питание хранится в отдельном `nutrition.json`: документ и точный незавершённый запрос записываются атомарно. Старое избранное переносится из `nutrition-preferences.json` с резервной копией и сохранением неизвестных ID. После входа синхронизируются дни, цели, свои рецепты и избранное через прежние `workout:read/write`. Конфликт сохраняет обе стороны и требует явного выбора; снимок цели и timezone созданного дня не подменяется. Экспорт аккаунта читает актуальные выбранные дни с сервера, гостевой экспорт помечен локальным. Проверки и ограничения: [QA-IOS07.md](docs/QA-IOS07.md).

Экран аккаунта показывает имя или логин, реальный статус привязки Telegram и идентификатор связанного аккаунта из Account API Keycloak. Профиль обновляется при открытии экрана, возвращении из браузера, по кнопке «Обновить профиль» и при ручной синхронизации. ID сверяется с проверенным аккаунтом API тренировок; профиль остаётся только в памяти и очищается при выходе. Нужна серверная настройка `configure_mobile_identity.py` с правом чтения `account:view-profile`; административные права приложению не выдаются.

## Каталог и нагрузка

Источник — каталог бэкенда, встроенный локально для работы без сети. Его Git-ревизия и SHA-256 закреплены в `catalog.lock.json`.

```sh
python3 scripts/sync_catalog.py ../podhod-backend
```

Импорт принимает только закоммиченный каталог. Поиск и библиотека используют канонические записи; точные связи прежних ID не изменяют снимки упражнений, заметки или историю. Нагрузка программы: прямые подходы + косвенные × 0,5. Все настроенные подходы пока считаются рабочими; отдельной разметки разминки нет.

Видео wger воспроизводятся системным AVKit-плеером; внешние ссылки открываются на сайте автора. Для видео нужен интернет. Авторство и лицензии: [CATALOG-LICENSE.md](CATALOG-LICENSE.md).

## Запас повторений и история упражнения

Во время тренировки у каждого подхода можно указать запас повторений: 0 — в отказ, 1–4 или 5+; отсутствие оценки не означает отказ. Оценка необязательна и редактируется до завершения тренировки, включая уже записанные подходы. Она сохраняется локально и синхронизируется с backend. Старые записи остаются без оценки. Перед первой записью архива v6 исходный архив v1–v5 сохраняется в резервной копии; прежняя версия приложения не должна открывать новый формат.

Из блока «В прошлый раз» и экрана прогресса открывается история конкретного упражнения: график веса, подходы, запас и сохранённые заметки по датам. Точные ID aliases каталога объединяют просмотр результатов старых и канонических ID, не изменяя снимки и UUID. Незавершённые подходы не попадают в график.
