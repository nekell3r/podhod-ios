# IOS-07: дневник питания

Проверено 1 ноября 2026. Android не изменялся. API дней, целей, своих рецептов и избранного уже выпущен отдельно; SQL-схема не менялась.

## Реализация

- Дни, четыре приёма пищи, продукты каталога, ручной состав и рецепты; редактирование массы и удаление с подтверждением. Граммы и порции различаются, готовая масса рецепта подтверждается отдельно.
- Ручные цели с датой начала и timezone, собственные рецепты с ингредиентами/шагами/готовой массой, избранное и JSON-экспорт выбранных дат.
- Снимки состава, цели и timezone не переписываются изменением рецепта/цели. Отсутствующие/null КБЖУ не становятся нулями. Значения источника не заменяются формулой 4/9/4.
- Отдельный `nutrition.json` внутри AccountWorkspaces. Импорт прежнего избранного сохраняет исходный файл, закрытую копию и неизвестные ID. Гость после принятия данных ротируется, включая восстановление прерванного переноса только питания.
- Локальный документ и pending request сохраняются атомарно. Повтор отправляет прежние requestID/revision/payload; новые правки получают следующий запрос после подтверждения. Устаревший receipt не восстанавливает удалённое. При конфликте обе версии копируются до дальнейшего редактирования и сохраняются до явного выбора.
- Запись проверяет owner и текущую OAuth-сессию; смена workspace пересоздаёт store/sync/UI. Устаревший редактор или подтверждение удаления не стирает более свежую запись. Снимок уже созданного дня нельзя заменить выбором локальной версии поверх другого server snapshot.

## iPhone 15

Только отдельный **Podhod iPhone 15 QA**, iOS 26.5, синтетические данные. После новых правил автоматизация переведена на headless CoreSimulator/XCUITest без открытия Simulator.app и смены фокуса. Максимум один свой симулятор; после каждого завершённого прогона он выключен. Тяжёлые пакеты выполнялись последовательно с максимум двумя задачами сборки.

| Сценарий | Фактическое подтверждение |
|---|---|
| Дневник/конфликт | Снимок главного экрана; синтетический гостевой конфликт объяснён, выбор без входа отключён |
| Еда | Поиск банана, 125,5 г → 121,7 ккал, сохранение в завтрак и удаление с подтверждением; соответствующие UI-assertions и снимок сохранённой строки |
| Цель | `testManualGoal`: ввод/сохранение 2000/100/80/220; проверены UI и сохранённый архив |
| Рецепт | `testCreateOwnRecipeWithIngredient`: ингредиент, масса, шаг, подтверждение готовой массы и успешное сохранение; keyboard Done работает |
| Экспорт | `testExport`: выбор дат и доступное действие JSON; основное действие доступно; пояснение диапазона частично усечено (неблокирующее замечание review) |

Изначальный общий UI-case остановился после успешного этапа еды на неоднозначном селекторе значения цели. Проверки разделены, остальные экраны доведены адресно; подтверждённая еда не прогонялась повторно. Промежуточные ошибки селекторов/фокуса и запуск с нулём выбранных тестов не считаются успешными проверками. Снимки и xcresult хранятся только в игнорируемых `.impeccable/review/` и `.build/`.

Для воспроизведения предназначена отдельная opt-in схема `PodhodUIQA`. Используй только собственный обычный iPhone 15 с синтетическим гостевым архивом: пустые цели/свои рецепты, без записи банана за выбранный день. Задавай точный UDID, `-parallel-testing-enabled NO`, одну simulator destination; после теста выключай только это устройство. Схема выпуска `Podhod` тестовый runner не включает.

## Исправление общего списка рецептов — 1 ноября 2026

Причина: `NutritionView` читал только `NutritionCatalog`, хотя рецепты аккаунта уже синхронизировались в `NutritionDiaryStore`. Вкладка теперь получает тот же store, что дневник; «Все» показывает оба источника, сначала мои рецепты. Фильтр «Все / Мои / Каталог» независим от категории. Поиск названия/ингредиента, время, белок на порцию и избранное применяются к обоим источникам. Общий список не записывает личные рецепты в публичный каталог и не меняет их UUID. Карточка моего рецепта читает актуальную запись по UUID, показывает состав/шаги/КБЖУ, избранное и переход в прежний редактор с expected snapshot.

**44 адресных core-теста, 0 ошибок**, включая две новые регрессии: 15 рецептов после JSON round trip остаются видны поиску с прежними UUID; категория, время и белок проверяются по фактической порции. Сохранены прежние проверки каталога, дневника и избранного. Debug build-for-testing успешен, максимум две задачи сборки.

`testRecipeLibraryCombinesSourcesAndFiltersOwnRecipes`: **1 UI-тест, 0 ошибок**, headless обычный iPhone 15, iOS 26.5. Синтетический гостевой архив с 15 рецептами; реальные записи пользователя не копировались в fixtures. Проверены «Все» при открытии, поиск 15-го рецепта, «Мои», исключение личного результата в «Каталоге», сброс поиска и встроенный рецепт, карточка личного рецепта, избранное/фильтр и перезапуск. Первый прогон остановился на чтении `value` вместо `isSelected` сегмента; после исправления селектора завершён этот же незавершённый сценарий. Успешные старые UI-сценарии отдельно не повторялись.

Просмотрены четыре снимка текущего UI: общий список, поиск в моих, каталог и карточка моего рецепта. После теста сверены JSON: все 15 документов/UUID и pending request рецептов, а также дневник сохранены; изменилось только избранное тестового рецепта. Test runner переустанавливает контейнер приложения, поэтому итоговый архив найден по metadata точного Bundle ID, без запуска второго устройства. Собственный QA-симулятор выключен. Captures/xcresult/синтетические архивы остаются в игнорируемых `.build/`; локальные инструкции обновлены через `update-agents-docs`.

Физический iPhone, подписанная установка через Feather и новые сетевые конфликты этим адресным UI-тестом не проверены. Формат хранения, backend и Android не менялись; серверная коллекция и прежние правила синхронизации остаются теми же. Опубликованный Release, receipt и SHA-256 проверяются отдельно после main workflow.
