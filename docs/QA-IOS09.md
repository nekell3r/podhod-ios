# IOS-09: отдых вне приложения

Реализация 1 ноября 2026, iOS 17+. Серверный API, SQL и Android не меняются. [Контракт](REST-PRESENTATION-CONTRACT.ru.md).

## Реализация

- Отдельный WidgetKit extension, ActivityKit с системным обратным отсчётом, вид отдыха и ссылки +30/закончить. Расширение получает только непрозрачный workspace ID, session UUID и состояние таймера; не читает архивы и не использует App Group.
- Ссылки открывают приложение. Перед изменением сверяются актуальные workspace/session/deadline, далее вызываются прежние `adjustRest`/`stopRest`. Точный Date передаётся в reference seconds без потери младшего бита; OAuth route не меняется.
- Платформенные операции сериализованы и проверяют generation после await. Смена аккаунта/тренировки, остановка и отключение убирают собственную Activity/уведомление. Ручное закрытие одной Activity учитывается, без самопроизвольного восстановления того же таймера. Дата и фактические timing-интервалы принадлежат WorkoutStore.
- Уведомление включается явно; отдельный ID не пересекается с утренним/вечерним протеином. Общий системный delegate переименован в `AppNotifications`; прежние protein preferences/ID сохранены. Тап по уведомлению открывает тренировку через тот же проверяемый URL.
- Настройки Live Activity и уведомления применяются сразу; параметры длительности отдыха по-прежнему сохраняются явной кнопкой. Цвета вынесены из Design.swift в `GymColors.swift` для реального использования обоими targets, значения не менялись.

**23 Python-проверки упаковки, 0 ошибок**. Отсутствующий/чужой/несовместимый extension и simulator binary отклоняются. Новая проверка действует локально и в CI; серверный receiver не менялся и продолжает прежний контракт приёма.

Debug build-for-testing успешен с embedded extension. Фактические main/extension plist в сборке имеют одинаковые version/build и minimum OS 17.0.

## iPhone 15

Один headless Podhod iPhone 15 QA, iOS 26.5, синтетический guest-архив с backup. Ни Simulator.app, ни видимые браузеры не открывались. После завершения собственный симулятор выключен; остальные устройства/контейнеры не затрагивались.

`testLiveActivityControlsAndBackgroundNotification`: **1 тест, 0 ошибок**. Системное разрешение, включение уведомления, запись подхода → отдых 120 с, background/expanded Dynamic Island, +30 через её ссылку с возвращением в приложение, остановка, последний подход → 15 с перед следующим упражнением, реальный системный banner «Отдых окончен» в фоне, тап → открытая тренировка с 0:00 и явное завершение. После остановки проверен архив: выполненные подходы сохранены, restUntil отсутствует, timing содержит границы реальных операций.

Визуальный просмотр первого capture обнаружил некорректный размер системного Date timer из-за fixedSize: функциональная ссылка работала, но числовая часть не рисовалась. Дефект исправлен ограниченной шириной таймера в каждой презентации. Адресный `testIslandTimerAndStopLink` прошёл (1 тест, 0 ошибок): конечный frame таймера 80×26,3 pt, видимое время 1:54 и работающая ссылка остановки. Уведомление/+30 повторно не запускались. Отдельный новый сценарий `testRestoredLockScreenPresentation` прошёл (1 тест, 0 ошибок): сохранённый отдых восстановлен после запуска, системная Lock Screen-презентация показана в Центре уведомлений, expanded Island и остановка доступны. Физическая блокировка при этом не имитировалась. Captures изменённых представлений обновлены; из первого сценария сохраняется доказательство неизменённого notification banner, а не компактного счётчика.
